# Research Data Analysis

把一次数据分析拆成可核查的步骤：**先确认数据，再查前提，后建模型**；每项结论都能追溯到具体的数据输出，材料不足时明确报告，而不是补造。

> 本 skill 固定的是"如何作出有依据的分析判断"，不是"每次都得到同一种结论"。

## 适用情形

- 已有数据（CSV / Excel / Stata / SPSS 导出）或清楚的变量说明，需要选择或检查分析方法
- 需要在建模前做数据检查：缺失、异常值、分布、重复、面板结构、共线性
- 需要写或审查 R / Stata / Python 分析代码
- 需要解读回归、Logit/Probit、面板固定效应、调节/中介、SEM/PLS-SEM 等结果，并区分统计结果与推断

## 不适用情形

- 不负责判断研究的理论贡献、选题价值或能否达到某期刊发表标准
- 不负责在缺少识别策略时"证明"因果关系
- 不生成、补全或修改原始数据；不替代研究者对测量是否匹配概念的判断
- 未经授权的保密数据（企业内部数据、访谈原始资料、审稿稿件中的数据）不应交给本 skill 处理

## Input

- **本轮研究问题**（必需）：要回答什么，自变量/因变量/调节/中介是什么
- **数据**：数据文件，或变量清单 + 样本说明（没有数据文件时只能做设计层面的检查，见 Step 1）
- **变量说明**（尽量提供）：每个变量的概念定义、测量方式、来源、时间范围
- **已有分析计划或代码**（可选）
- **导师要求 / 认可的示例**（可选，没有则写"暂无"）

## Scripts

### 数据概况与前提初检

```bash
python scripts/data_profile.py \
  --data data/my_data.csv \
  --vars y x1 x2 control1 \
  --id firm_id --time year \
  --output outputs/data_profile.json
```

输出：样本量、变量类型、缺失率、疑似缺失码（−999 等）、零值占比、描述统计、偏度、异常值计数、重复记录、面板是否平衡、组内变异占比、高相关变量对，以及（安装 statsmodels 时）VIF。
脚本只做描述性检查，**不做任何删除、填补或变换**。工具不可用时，按 `references/assumption-checklist.md` 手动逐项检查并在报告中注明"未运行脚本"。

## Workflow

### Step 1: 确认实际拿到了什么
- 列出实际收到的文件、变量、样本量、时间范围
- 区分"已拿到数据"与"只有描述"：只有描述时，后续只能给出**设计层面建议**，不能报告任何统计结果
- 缺少的材料（变量定义、编码表、问卷题项、样本筛选过程）逐项列出，并说明会影响哪些判断

### Step 2: 研究问题 → 变量 → 测量
- 为每个核心构念同时写出**概念定义**和**实际测量**，比较二者覆盖的对象、层次（个人/团队/企业/行业）和时间范围
- 不因变量名称相同就认定测量相同；名称与测量不一致时标注出来交给研究者判断
- 明确分析单位、因变量类型（连续/二分/计数/有序/截断）、数据结构（截面/面板/嵌套/实验）

### Step 3: 数据检查（建模之前）
- 运行 `scripts/data_profile.py` 或手动检查：缺失、异常值、分布、重复、面板平衡、共线性
- **缺失码**：逐个数值变量检查 −999、−99、9999 等疑似缺失码，确认它们没有被当作真实数值参与缩尾、标准化或回归
- **零值集中**：核心解释变量大量为 0 时，记录"始终为 0 的个体数"，后续要单独检验"有/无"的差异
- **变异来源**：面板数据中，报告核心变量的组内/组间方差占比；组内变异很小时，说明结果主要靠个体间比较识别
- 只报告发现，不擅自处理。任何删除样本、填补缺失、缩尾/取对数，都要写明理由并**由研究者确认**后才执行

### Step 4: 选择方法
- 按 `references/method-decision-tree.md` 给出 1 个主方法 + 必要的备选方法，并说明选择依据（因变量类型、数据结构、识别需要）
- 有导师或课程材料的要求时，标注"本项目要求"；来自方法文献的，保留出处；为操作方便新增的，标注"暂定做法"

### Step 5: 检查前提，再建模
- 按 `references/assumption-checklist.md` 逐项检查所选方法的前提
- 前提不满足时：报告违反程度 → 给出可选的修正方法（稳健标准误、换模型、变换等）→ 由研究者决定
- 发现测量与概念不一致、或数据结构与原计划不符时，**返回 Step 2 / Step 4**，不要硬把流程走完
- 对关键结果必做以下三项（参考文件缺失时也必须执行）：
  1. **影响力单位检验**：逐个剔除聚类单位（国家/企业/行业），至少剔除影响最大的几个单位后重估关键系数；领先–滞后、事件研究和异质性结果尤其要做。报告结论是否依赖少数单位
  2. **一次只改一个设定**：相邻两列（或基准与稳健性结果）之间若同时改变了多个设定（相关结构、固定效应、控制变量、样本、标准误类型），逐项单独改变，说明差异分别来自哪一项，不把多项变化的合计效果归因于其中一项（如"控制内生性后"）
  3. **工具变量**：报告工具变量的分布（多少单位取非零值）、简约式结果、与主回归相同固定效应设定下的 2SLS；第一阶段 F 值说明所用的判断标准是否适用于聚类/异方差情形

### Step 6: 建模与代码
- 代码写成可直接运行的脚本，注释说明每一步对应的研究问题
- 优先使用研究者指定的软件（R / Stata / Python）；未指定时询问或默认 Python
- 报告结果时保留原始输出（系数、标准误、p 值、样本量、拟合指标），不只给"显著/不显著"
- **复现已有论文/代码时**：逐表逐列列出"论文值 vs 复现值"；核对表注与代码是否一致（标准误类型、样本量、固定效应）；代码中硬编码的数字（F 值、样本数）要用实际输出核对；无法复现的列如实标注原因

### Step 7: 解释结果（三层分开写）
- **统计结果**：模型实际报告了什么（数值 + 输出位置）
- **基于结果的解释**：在当前设计下能支持的判断
- **待检验的设想**：超出数据能支持范围的推断、可能的替代解释、需要的稳健性检验

### Step 8: 列出需研究者核验的事项
- 所有需要人工判断的位置（样本处理、模型选择、因果表述、测量效度）汇总成清单

## 审慎审稿人视角

```text
以管理学/信息系统顶刊方法审稿人的标准审查本次分析。
相关不是因果：没有可信的识别策略（实验、工具变量、DID、断点、
面板固定效应 + 时序逻辑等）时，不使用"影响""导致""提升"等因果措辞。
重点追问：内生性来源（遗漏变量、反向因果、选择偏差、测量误差）、
共同方法偏差（同源问卷数据）、样本选择、显著性是否依赖特定设定。
```

## Rules

- **先查前提，再建模型**：未完成 Step 3 和 Step 5，不报告模型结论
- 不编造数据、样本量、系数、p 值、题项或文献；没有运行的分析不写成已运行
- 只有变量描述、没有数据时，明确说明"无法报告统计结果"
- 不擅自删除样本、填补缺失或变换变量；所有数据处理都留下记录并经研究者确认
- 无识别策略时不用因果措辞；p < 0.05 不等于效应重要，同时报告效应量
- 同源问卷数据必须提示共同方法偏差检查；面板数据必须说明聚类/固定效应的选择
- 关键结论必须做影响力单位检验；结果依赖单个或少数单位时，必须在解释中写明
- 不同设定之间的差异要逐项归因，不把同时发生的多项改变归功于其中一项
- 异质性结论要有组间差异检验，不能只比较两组各自是否显著
- 不因变量名称相同就认定测量相同；按研究设计（定量实证 / 实验 / 二手数据）调整检查重点，不强行套用同一套字段
- 工具不可用、文件读不了、代码运行失败时，如实报告并停止该步骤，不假装完成
- 每次分析保留记录（日期、模型、skill 版本、处理步骤、人工核查结果），便于按 AOM 要求披露 AI 使用
